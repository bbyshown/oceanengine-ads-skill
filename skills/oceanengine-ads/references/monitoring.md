# 只读监控与数据解释

## 设置当前工作区监控

```sh
python3 "$S/scripts/setup.py" monitor-config --account main --project V02
python3 "$S/scripts/monitor_ads.py" --once
```

项目存在多广告时加`--promotion-id`。这会从实时库存生成本地状态目录下的`monitor-policy.json`，不继承作者的账户或广告。示例字段见[monitor-policy.example.json](monitor-policy.example.json)，金额和观察线只是提醒示例，可按用户业务要求调整。

当前监控只调用inventory/report，**不会自动停投、改价、加预算、删除或创建广告**。将`automatic_pause`改为true会被程序拒绝，不能冒充已具备自动止损。用户若明确要求自动关停，需要另外设计、确认并验收具体规则及执行范围，不能仅改提示词绕过当前只读边界。

每次执行保存快照、上次成功状态及去重记录。读取失败不会把旧数据覆盖为0；连续失败才提醒一次。默认观察开始满6小时才判持续无量；回收偏低需消耗/激活样本/观察时长全部满足，且两次检查相隔至少25分钟。样本少不触发“效果差”判断。

## 定时任务

仅在用户要求周期检查时创建。先查已有自动任务，优先更新，不重复创建。使用宿主提供的automation_update工具，将任务挂在当前聊天，按用户指定频率执行现成命令；用户未指定频率时可建议30分钟。

任务说明应保留实际工作区绝对路径、`OCEANENGINE_MANAGEMENT_CONFIG`/`OCEANENGINE_ADS_HOME`的必要路径（不含密钥）、明确账户与目标、最新“只提醒”要求和停止条件。读取`should_report`，没有有意义变化就保持安静；有新异常或需要用户处理时再报告，不能每次触发都发例行消息。

本地运行依赖电脑、任务宿主和工作区可用。若要求离线也能监控，需要另外部署服务器调度并验收；不要把本地定时命令当成已经配置的服务器守护。

## 分析口径

- 用平台汇总ROI，不平均各小时ROI。`attribution_micro_game_0d_roi`按比值解释，例如1.40表示140%；`ctr`通常已是百分数，20.00表示20%，不要再次乘100。
- 显示为0.13和0.09等已四舍五入金额，未必能精确反推出平台原始ROI。
- 七日ROI返回一个当前值不等于七日队列已经成熟；不能按1天的累计回收宣称7日达标。
- 没有曝光/激活时，CTR/CPA/ROI默认0不具有有效样本意义。少量激活不足以证明可规模化。
- 平台记录激活/IAA收入，证明已有对应数据；完整回传、去重、归因以及与游戏后台收入是否一致仍需单独核对。
- 余额接口拒绝授权时不能推断资金充足或不足；明确报告缺失能力，使用经授权可见的后台信息补证。
